## Commands

Run these from inside the relevant repo, not from the workspace root.

```sh
# garage-log / home-log (Astro)
npm run build            # static build to ./dist/
npm run publish          # interactive: diff, confirm, commit, push (private repo first)
npm run check-recalls    # garage-log only: refresh NHTSA recall data
npm run monthly-digest   # garage-log only

# redfearn-group.github.io (Eleventy)
npm run build            # to ./_site/
npm run og               # regenerate OG card images
npm run new-post         # scaffold an Insights post

# redfearn-brand
node sync.mjs            # copy brand.css and kit/ into every consumer on disk
node sync.mjs --check    # report drift without writing; exits 1 if any copy differs
```

There is no test suite in any repo. `npm run build` is the check that a change is valid.

**Dev servers: use `preview_start` with the names in `.claude/launch.json`**, not `npm run dev` in a shell. Configured names are `redfearn-group-site` (8080), `garage-log` (4321), `home-log` (4323). The Astro apps are served under their base path, so browse `http://localhost:4321/garage-log/`, not the bare origin.

## Architecture

### YAML is the database

Neither tracker has a database or a write path in the deployed site. Vehicle and item data are YAML files committed to the repo, so git history is the audit trail. `src/lib/data.ts` reads them at build time and every page is static HTML. Data is edited by hand or by Claude, then committed.

```
data/vehicles.yaml  (or items.yaml)   # index; one entry per vehicle/item
data/vehicles/<slug>/                 # slug must match the folder name
  schedule.yaml         maintenance-log.yaml     tasks.yaml
  admin-dates.yaml      documents.yaml           watch-list.yaml
  recalls.yaml          recall-remedies.yaml     # garage-log only
  private.yaml                                   # gitignored, never committed
```

### The `itemType` join is the thing to get right

Due status is computed in `src/lib/status.ts` by matching `schedule.yaml`'s `itemType` against entries in `maintenance-log.yaml` carrying the **same** `itemType`. A maintenance entry with a good `description` but the wrong or missing `itemType` is invisible to the schedule table and the item still shows as never done. When logging that something was serviced, add a properly tagged entry rather than only appending prose to an existing one.

Schedule item `name` fields carry a long sourcing citation after `" — "`. `splitScheduleItemName()` splits on that exact separator to render the short label with the citation behind a disclosure. **That em-dash is load-bearing**, unlike prose em-dashes (see Voice below).

### Shared brand system

Two things are authored in `redfearn-brand` and **vendored** outward by `sync.mjs`:

- `brand.css`, into every property (`src/css/brand.css` for the site, `src/styles/brand.css` for the apps).
- `kit/*.ts`, into `src/lib/kit/` in the four Astro apps only. The modules use `import.meta.env` and js-yaml, so they mean nothing to the Eleventy site, which takes `brand.css` and nothing else.

A `vendor-drift.yml` GitHub Action in each consumer fetches canonical from `main` and fails the build if any vendored copy differs.

To change a value: edit it in `redfearn-brand`, run `node sync.mjs`, **push `redfearn-brand` first**, then the consumers. Pushing a consumer first fails its drift check, and for the kit it fails harder: the check fetches by URL, so a kit file that does not exist on `main` yet is a 404 rather than a diff. Never edit a vendored copy.

### The kit

Shared, app-agnostic helpers. Deliberately small: about 100 lines. Anything that needs to know what a vehicle or a meeting is belongs in the app, not here.

| Module | Exports |
| :--- | :--- |
| `kit/base.ts` | `withBase(p)`, prefixing an internal link with the Pages base path |
| `kit/date.ts` | `formatDate`, `parseDate`, `daysBetween`, `today`. All DD MMM YYYY, all regex-parsed |
| `kit/yaml.ts` | `DATA_DIR`, `readYaml(path, fallback)`, `readData(relPath, fallback)` |

**Dates never travel through `new Date(isoString)`.** That parses a bare `YYYY-MM-DD` as UTC midnight and renders it in local time, printing the previous day anywhere west of Greenwich. Every date in these repos is a calendar date with no time component. The kit parses by regex for exactly this reason, and a page that reaches for `toLocaleDateString` is reintroducing the bug.

The `.mjs` files under `scripts/` in each app are run directly by node and are **not** part of the Astro build, so they cannot import the kit's TypeScript. Duplication between a script and the kit is a known limitation, not an oversight.

Three layer scopes set the accent role. `:root` is Identity (brand red, site chrome), `.content-layer` is Content (ember to gape, case studies), `.app-layer` is Product (dark surfaces, cream text, red as decoration only). The apps set `class="app-layer"` on `<html>` and are dark unconditionally, not via `prefers-color-scheme`.

Load order matters: `brand.css` must come before the property's own stylesheet. Property CSS should never redefine `--rg-*` or `--status-*`, and should use the semantic tokens (`--accent`, `--border`, `--text-muted`, `--status-*-fg`) anywhere a value must change between layers. Raw palette tokens do not adapt.

**The palette is a closed set.** Do not introduce off-system colors, including lightened variants to solve a contrast problem. Reviewed schemes and rejected candidates are documented in `redfearn-brand/skill/references/logo-system.md` and archived in the `logo-variant-review` repo.

### Public/private split

The trackers' repos are public and git push access is the whole security model. Two escape hatches:

- `data/vehicles/*/private.yaml` is gitignored: door codes, policy numbers, third-party contact info. It has no git-history backup, so it is also mirrored to Google Keep.
- Uploaded documents go to the private sibling repo under `documents/<slug>/<category>/`, as a blanket rule rather than a per-file judgment call. The public repo's `documents.yaml` stores only metadata, and the site shows a "stored in private repo" note with no download link.

Every field on the interfaces in `src/lib/types.ts` renders publicly, since `data.ts` loads YAML straight through with no field-level filtering. A new field carrying account numbers or contract details belongs in `private.yaml`, not on the type.

## Voice

All Brady-facing copy, including READMEs, repo descriptions, and rendered YAML content, follows the `redfearn-group-style` skill. The hard rule: **no em-dashes in prose**, restructure with a period, comma, or colon. Exceptions are the `" — "` schedule-name separator above and the standalone `—` used as a null-value placeholder in tables.

## Deliberate decisions, do not silently "fix"

- **VIN-specific recall completion status is manual.** The NHTSA API lists campaigns for a make/model/year but cannot say whether a given VIN was repaired. Building a .gov scraper or paying for a third-party API was rejected on 2026-07-10. `recall-remedies.yaml` is hand-maintained per vehicle and is separate from `recalls.yaml` precisely so the monthly auto-fetch cannot clobber it. The reasoning is inline in `scripts/check-recalls.mjs`.
- `scripts/monthly-digest.mjs` duplicates the `DUE_SOON_MILES` / `DUE_SOON_DAYS` thresholds from `src/lib/status.ts`. Change both together.
